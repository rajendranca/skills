# Architecture governance checkpoint
Set out decision context, business constraint, architecture principles, constraints, relevant system context, options, risk exposure, chosen pattern or proposed deviation, security/privacy controls, operability, support, data/observability, testing implications, migration/rollback, cost rationale and verification evidence.
Distinguish (a) technical recommendation, (b) user leadership preference, (c) formal architecture/security approval. Provide the minimum viable artifact required for the next gate; offer full ADR only for material decisions. Escalate cross-domain compromises and hidden long-term coupling.
