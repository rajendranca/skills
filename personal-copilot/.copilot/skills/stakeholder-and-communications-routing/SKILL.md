# Stakeholder routing
Identify parties by **role**, not invented person. Establish sponsor, decision owner, execution owner, accountable architecture voice, necessary consultation, notified audience and decision gate. Minimum sufficient set of stakeholders; avoid meeting inflation.
Consider business/product sponsor, BA, pod lead(s), senior manager, delivery manager, chief QA lead, operations/support, cybersecurity/data risk, infrastructure/platform, integration partners, finance/vendor and governance board only when justified.
Produce: engagement-by-phase map, pre-read, purpose, required decision, suggested agenda, and two-sentence message for each key audience. Mark authority and routing as *proposed pending validation*.
