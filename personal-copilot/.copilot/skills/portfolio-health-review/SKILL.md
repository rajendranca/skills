# Portfolio health: management by exception
Review supplied pod summaries and prior baseline if provided. For each initiative identify last-known milestone/commitment, current evidence, meaningful change, blockers, architecture/QA concerns, dependencies, risk trend, decision required, and owner.
Never invent a Red/Amber/Green signal; if evidence is insufficient use 'unverified' and specify what would verify it. Distinguish slipped commitment from planning estimate. Present a one-page pulse, top risks, cross-pod dependencies, decision queue, and unresolved inputs for delivery manager/chief QA lead/senior managers.
Keep downward detail in an appendix; default senior-leadership brevity.
