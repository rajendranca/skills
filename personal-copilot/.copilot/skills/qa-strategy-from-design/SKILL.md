# Procedure
Read design artifacts. Build risk-based test scenarios covering contracts, edge cases, functional, security, integration, resilience, performance, operations and migration. Identify test data, environments, ownership, evidence and entry/exit criteria. Do not claim tests were executed.

# Evidence discipline
Use workspace documents as primary evidence; distinguish facts and assumptions, and cite file names and relevant headings. Never assume a code repo is available.
