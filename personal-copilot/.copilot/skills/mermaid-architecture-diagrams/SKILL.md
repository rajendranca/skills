# Procedure
Choose the right Mermaid diagram style for the audience. Name components and interfaces consistently; show directionality, boundaries, on-prem/cloud regions, failure paths and async links. Keep diagrams readable and include a legend. Produce code block compatible with Markdown preview plus assumptions and follow-up questions.

# Evidence discipline
Use workspace documents as primary evidence; distinguish facts and assumptions, and cite file names and relevant headings. Never assume a code repo is available.
